# Chronicle v1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Chronicle 1.0.0 for Windows x64 as a selectable-directory NSIS installer and a self-contained portable ZIP, with accurate branding and release documentation.

**Architecture:** Repository-root selection is isolated in the Rust desktop bootstrap so the portable marker has one deterministic interpretation: use the executable directory's `Chronicle-data`; otherwise use the existing app-local path. The frontend receives its version from Vite build configuration and renders a copied app-icon asset in the About panel. Packaging stays reproducible through Tauri's NSIS configuration plus one PowerShell portable-packaging script.

**Tech Stack:** Rust 2024, Tauri 2, Vue 3, Vite 7, Vitest, PowerShell, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-08-v1-release-design.md`

## Global Constraints

- Release only Windows x64 version `1.0.0`.
- NSIS must use `installMode: "both"`, retain standard install-directory selection, and keep installed data in `%LOCALAPPDATA%\com.thermalex.chronicle\Chronicle`.
- A portable package root must contain `Chronicle.exe`, empty `portable.marker`, `Chronicle-data/` created on first launch, and no App Local Data fallback or migration.
- Keep Tauri's existing Windows icon and add only an NSIS bundle target; do not introduce updater support or code signing.
- About must show the actual application icon, the build-injected version, and `ThermalEX` as author.
- Commit the four supplied screenshots and render them in the README.
- Release exactly installer, portable ZIP, and `SHA256SUMS.txt`; release notes must state that the Windows build is unsigned.

**Interfaces:**

- Produces: `pub fn resolve_repository_root(executable: &Path, app_local_data: &Path) -> std::io::Result<PathBuf>`.
- Rule: a sibling `portable.marker` yields `<exe-parent>/Chronicle-data`; absent marker yields `<app-local-data>/Chronicle`.

- [ ] **Step 1: Write the failing Rust tests**

```rust
#[test]
fn portable_marker_uses_sibling_data_directory() {
    let temp = tempfile::tempdir().unwrap();
    let executable = temp.path().join("Chronicle.exe");
    std::fs::write(temp.path().join("portable.marker"), "").unwrap();
    assert_eq!(
        resolve_repository_root(&executable, Path::new("C:/AppData")).unwrap(),
        temp.path().join("Chronicle-data")
    );
}

#[test]
fn normal_installation_uses_app_local_data() {
    let temp = tempfile::tempdir().unwrap();
    assert_eq!(
        resolve_repository_root(&temp.path().join("Chronicle.exe"), Path::new("C:/AppData")).unwrap(),
        PathBuf::from("C:/AppData").join("Chronicle")
    );
}
```

- [ ] **Step 2: Run test to verify it fails**

Run: `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml storage_root`

Expected: FAIL because `storage_root` and `resolve_repository_root` do not exist.

- [ ] **Step 3: Implement the resolver and inject it into Tauri setup**

```rust
pub fn resolve_repository_root(executable: &Path, app_local_data: &Path) -> io::Result<PathBuf> {
    let executable_directory = executable.parent().ok_or_else(|| io::Error::other("executable has no parent directory"))?;
    if executable_directory.join("portable.marker").is_file() {
        Ok(executable_directory.join("Chronicle-data"))
    } else {
        Ok(app_local_data.join("Chronicle"))
    }
}
```

In `lib.rs`, call `resolve_repository_root(&std::env::current_exe()?, &app.path().app_local_data_dir()?)?` before `LocalRepository::open`. `LocalRepository::open` owns creation of the resolved root, so no AppData lookup is possible in portable mode.

- [ ] **Step 4: Run the focused test and the desktop crate tests**

Run: `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml storage_root`

Expected: PASS, two resolver tests pass.
