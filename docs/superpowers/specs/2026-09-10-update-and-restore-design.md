# 自动备份恢复抑制与更新检查设计

## 目标

恢复历史快照时，Chronicle 不得将恢复操作写入的文件事件当作用户修改而创建自动备份。应用需要在“关于”页提供正式版/测试版渠道、启动自动检查、手动检查，并在有新版本时显示统一格式的更新弹窗；用户可复制链接、在浏览器打开或下载并执行 Windows NSIS 安装包。

## 恢复监听抑制

`AutoBackupManager` 为每个存档维护恢复抑制状态。`restore_snapshot` 开始前进入无限期抑制并清掉已排队自动备份；恢复成功后抑制延续一个当前“合并时间”窗口，恢复失败则解除抑制。文件观察回调在抑制期间直接忽略事件，因此恢复前安全快照仍保留，而恢复写入绝不会额外产生“自动备份”。

## 更新来源与渠道

客户端只读取 `ThermalEX/Chronicle` 的 GitHub Releases API。正式版渠道选择最新非草稿、非预发布 Release；测试版渠道可选择最新非草稿 Release（包括预发布）。版本按 SemVer 比较，只有远端版本严格新于当前版本才显示更新。设置保持 `formatVersion: 3`，新增 `updateChannel: "stable" | "beta"`，默认 `stable`；已有 `checkForUpdates` 保持默认开启且迁移兼容。

## 关于页与更新弹窗

将“自动检查更新”从“软件”页移动到“关于”页。关于页新增渠道下拉、启动时检查开关、手动检查按钮和 GitHub Release 链接。启动检查无更新或失败时静默；手动检查用现有提示反馈结果。

发现更新后，应用显示可关闭的模态框：版本、发布日期、Release 正文和安装包信息。操作从次到主依次为“复制下载链接”、“在浏览器打开”、“下载并安装”。关闭按钮不改变更新设置。

## 下载与执行

仅接受 GitHub `ThermalEX/Chronicle` Release 的 x64 NSIS `.exe` 资产。原生命令下载到 Windows 下载目录的临时文件，计算 SHA-256；如 Release 中有 `SHA256SUMS.txt`，必须匹配后才能改名并启动安装器。安装器启动成功后 Chronicle 退出；没有 NSIS 资产时保留浏览器和复制链接操作，但禁用直接安装并说明原因。下载和启动始终需要用户点击，不静默下载或执行。

## 更新日志规范

已发布 Release 的正文汇总在 `docs/changelog.md`；GitHub 的 Release 页面负责显示版本大标题，正文不重复 `Chronicle vX.Y.Z`。更新弹窗以安全的纯文本预格式化方式展示正文，不解析 HTML。

## 验收

- 恢复文件事件不会创建自动快照；恢复安全快照不受影响。
- 设置迁移默认正式版渠道，保留原有自动检查开关。
- 稳定渠道忽略预发布；测试渠道可发现预发布；相同或较低版本不提示。
- Release 弹窗能关闭、复制链接、浏览器打开；只有受信任的 x64 NSIS 资产可直接安装。
- 下载 SHA 与 `SHA256SUMS.txt` 不一致时不启动安装器。
