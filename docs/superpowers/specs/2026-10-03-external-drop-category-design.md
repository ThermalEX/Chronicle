# 外部路径拖入与创建时选择分类设计

## 目标与范围

用户可从 Windows 资源管理器把文件或文件夹拖入 Chronicle，核对后创建存档；创建时可明确选择分类。多条路径默认组成**一个存档的多个来源**，不按游戏自动拆分。此功能只改变加入来源的入口，不改变快照、云同步、Steam/Galgame 扫描或已有分类数据模型。

## 交互

- 外部文件进入窗口时显示简洁的全窗接收提示；松开后校验路径，打开现有“新建存档”弹窗并预填来源。必须由用户确认创建，绝不在松开鼠标时自动备份或同步。关闭弹窗则不产生存档。
- 多条有效路径进入同一存档来源列表。不可访问或不支持的路径跳过并明确列出；全部无效时只显示错误。重复路径按 Windows 路径规则去重。正在显示其他弹窗、新手教程或不可操作状态时，不接收外部拖入。
- 创建弹窗增加分类选择，默认当前选中的有效分类；位于“全部存档”时默认不分类。可在创建前改成其他分类或不分类；分类列表支持较多项目及长名称。编辑现有存档时仍使用当前分类移动入口，不借此次改动重做编辑流程。
- 原有分类、存档拖往分类或回收站的操作继续可用；回收站仍需现有删除确认。单击、拖动和键盘操作不能互相误触发，Esc 可取消正在进行的内部拖动。

## 实现边界

- Windows Tauri 启用原生 `DragDropEvent` 获取文件系统路径。由于 WebView2 下此模式不支持当前 HTML5 内部拖放，内部存档／分类拖动改为指针事件驱动，保留现有移动操作的语义和视觉反馈；分类菜单和键盘可用路径保持不变。
- 新增窄范围的后端路径描述接口，只读判定文件／目录、存在与可访问性；真正创建仍走现有资料库接口及其校验。外部拖入只打开创建弹窗；不执行 EXE、不自动扫描游戏存档、不修改拖入的文件。
- 路径状态、去重和默认分类在前端创建流程中处理；最终提交仍由资料库核对来源和分类。拖入与文件选择器共用同一来源列表，避免两套导入逻辑。补齐中英文文案和遮罩的无障碍描述。

## 验收

- 单个文件、单个目录、多个混合路径、中文／日文路径均能打开预填的创建弹窗；取消无写入，确认后来源和分类正确。
- 重复、已移动、无权限与部分无效路径得到明确反馈，不会生成空存档或重复来源；弹窗打开时拖入不会覆盖草稿。
- 分类选择默认当前分类，可改选或选无分类；若默认分类在确认前消失，明确回退或提示，不隐式写入错误分类。
- 现有内部分类／存档拖动、回收站确认、菜单移动和键盘操作回归通过；外部拖入不触发内部拖动。运行前端及相关 Rust 测试，在 Windows 桌面端验证实际资源管理器拖入。
