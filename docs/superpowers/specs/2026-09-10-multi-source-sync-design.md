# Chronicle 多源同步与存档活动栏设计

## 目标

将云端同步从单一 `activeSourceId` 升级为多个可独立启停的来源。新来源默认暂停；用户明确启用后，存档页的同步和自动上传才会并行发送到该来源。暂停来源仍可在云端仓库页进行手动同步、上传、下载和管理。

同时收拢存档页的重复创建入口，改造时间节点详情为按需展开的活动栏，并把短暂的页面级快照进度替换为创建按钮自身的平滑进度状态。

## 配置与迁移

- `CloudSource` 增加 `syncEnabled: boolean`。
- 保留 `activeSourceId` 一次版本作为旧配置迁移输入；新的持久化格式不再依赖它进行同步调度。
- 加载旧配置时：旧 `activeSourceId` 对应来源迁移为 `syncEnabled: true`，其他来源为 `false`。没有有效旧来源时，所有来源暂停。
- 新建 WebDAV、GitHub、OpenDAL 来源均以 `syncEnabled: false` 创建，不会自动启用、不改写其他来源状态。
- `CloudSettings.enabled` 表示云端功能已配置；是否参与自动同步只由各来源的 `syncEnabled` 决定。

## 云端设置界面

- 移除“当前同步源”下拉菜单与“当前使用”徽章。
- 每个来源卡片的删除按钮左侧新增一个状态动作：
  - 暂停时显示绿色播放三角，标题为“开始同步”；点击后启用该来源。
  - 同步中显示蓝色暂停图标，标题为“暂停同步”；点击后暂停该来源。
- 卡片标题显示“同步中”或“已暂停”，作为文字状态而非只用颜色表达。
- 云端仓库页将 `activeSourceId` 的页面职责替换为仅在对话框生命周期内存在的 `repositorySourceId`；该选择用于浏览和手动操作某个来源，不修改其 `syncEnabled`。

## 同步行为

- 存档页“同步”及创建快照后的自动上传收集所有 `syncEnabled` 来源并使用 `Promise.allSettled` 并行执行。
- 每个来源调用既有 Rust 命令，保持来源级错误隔离；单个失败不取消其他上传。
- 全部成功时显示成功摘要；部分或全部失败时显示失败来源及原因，同时写入诊断记录。
- 若没有启用来源，存档页同步打开云端设置并提示用户点击任一来源的开始同步按钮。
- 云端仓库页的手动操作始终按当前浏览的 `repositorySourceId` 执行，即使该来源暂停。

## 存档页交互

- 顶部“创建备份”按钮移除，保留时间节点区域唯一的“创建新快照”入口。
- 右侧详情栏重命名为“活动栏”：未选择时间节点时仅显示精简提示，不显示详情内容；选择后显示该时间节点详情、备注与恢复操作。
- 移除页面级 `operation-progress`，防止极短任务造成内容下移。
- “创建新快照”按钮在执行时禁用，保留其固定尺寸和文本；按钮背景使用伪元素从左至右平滑填充，进度由现有快照读取回调驱动。扫描阶段使用不定进度动画，已知总文件数后切换为百分比填充；完成或失败后平滑退场。

## 验证

- 设置迁移测试：旧 `activeSourceId` 只迁移启用一个来源；新来源默认暂停。
- 同步调度测试：所有启用来源并发执行；暂停来源不被存档页同步调用；一个失败不阻止其他来源。
- 云端仓库手动操作测试：暂停来源仍可作为浏览/操作目标。
- 前端组件测试：播放/暂停切换不改变其他来源，新来源不自动启用。
- 快照进度工具测试：扫描阶段与已知进度阶段生成正确按钮状态。
- 运行完整前端测试、生产构建与桌面端 Rust 测试。
