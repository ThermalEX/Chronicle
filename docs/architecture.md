# Chronicle 架构设计

Chronicle 将用户选中的文件或文件夹统一建模为“条目”，将某一时刻的内容建模为不可变“快照”。分类属于本地视图，不改变快照内容。一个条目可以同时拥有本地副本和 WebDAV 副本，各副本通过同一份快照清单确定差异。

## 核心模型

- `Entry`：被管理的文件或文件夹，包含路径、显示名、分类、备份策略和恢复策略。
- `Snapshot`：条目在某一时间点的不可变版本，包含父快照、创建时间、来源设备、大小、内容哈希和对象引用。
- `Object`：实际存储的数据对象。首个版本采用“一次快照一个归档文件”，接口保留以后按内容分块和去重的能力。
- `Repository`：一个本地或 WebDAV 存储位置，保存对象、清单和设备信息。
- `SyncJob`：一次可恢复、可重试、可记录进度的同步任务。
- `Category`：本地分类和筛选信息，不参与远程内容寻址。

## 数据布局

本地 SQLite 只保存索引和运行状态，归档对象独立存放。数据库损坏时可以通过扫描清单重建索引。

```text
chronicle/
  v1/
    repository.json
    entries/<entry-id>.json
    snapshots/<snapshot-id>.json
    objects/<hash-prefix>/<content-hash>
    devices/<device-id>.json
    tombstones/<snapshot-id>.json
```

远程写入先上传临时对象，校验完成后再发布快照清单。清单最后写入，避免网络中断产生一个指向残缺对象的可见快照。快照 ID 和内容哈希全局唯一，同步只追加缺失对象；同一条目在多设备产生的新快照形成分支，不静默覆盖。

## 模块边界

```text
apps/
  desktop/                 Tauri 2 + Vue 3 桌面端
crates/
  chronicle-core/          领域模型、用例边界、错误语义
  chronicle-storage/       SQLite、归档、本地对象存储适配器
  chronicle-sync/          差异计算、任务状态机、WebDAV 同步
docs/
  architecture.md
```

`chronicle-core` 不依赖 Tauri、SQLite 或 WebDAV。界面只能调用应用用例，不直接访问数据库和文件系统。存储与同步通过端口接口接入，使单元测试可以使用内存适配器，也允许以后增加 S3、SMB 或其他后端。

## 关键流程

创建快照时先稳定读取源路径，生成临时归档，计算哈希并执行完整性校验，再原子移动到对象库，最后提交 SQLite 事务和快照清单。恢复默认写入临时目录，校验完成后替换目标；覆盖前由恢复策略决定是否创建安全快照。

同步流程分为扫描、比较、传输、校验和提交五步。任务进度持久化，应用退出或网络中断后可以续传。自动同步使用任务队列和单实例执行器，同一仓库的写入串行化，不在文件监听回调中直接执行备份。

## 开发阶段

1. 完成本地条目、分类、手动快照、查询和恢复闭环。
2. 加入计划任务、保留策略、完整性检查和导入导出。
3. 实现 WebDAV 仓库、手动同步、断点重试和冲突展示。
4. 加入文件变化触发、自动同步、多设备分支处理和远程清理。
5. 根据真实数据评估分块去重、加密仓库和更多远程后端。

每个阶段都以领域测试、适配器集成测试和真实目录端到端测试验收。数据库迁移、远程清单格式和归档格式必须带显式版本，不依赖界面版本推断。
